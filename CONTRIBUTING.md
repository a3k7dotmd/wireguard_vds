# Контрибуция

Спасибо, что хотите помочь.

## Перед коммитом

Прогоните локально то, что прогонит CI:

```sh
make lint
make test
```

PR с красным CI не мерджится — pipeline тривиальный, [`.github/workflows/ci.yml`](.github/workflows/ci.yml).

## Стиль

Скрипты прошли проход shellcheck со флагом `-S style`. Чтобы регрессий не было, держим:

- `#!/bin/bash` первой строкой каждого скрипта.
- Все подстановки переменных — `"${VAR}"` (фигурные скобки + кавычки), включая heredoc'и.
- `read -r` всегда — без `-r` backslashes мангаются.
- `cd ... || exit 1` — иначе после неудачного `cd` относительные пути уйдут не туда.
- Никаких `set -e` в коротких ручных скриптах, но `set -euo pipefail` обязателен в тестах и любых скриптах, которые предполагается запускать неинтерактивно.
- Новые подкоманды добавляются в `wgctl` (case-arm) и `scripts/menu.sh` (пункт), плюс в `Makefile`-цель если она admin-уровня. Один новый файл `scripts/<name>.sh` на команду.

## Pull Request

1. Ответвитесь от `master`.
2. Соберите изменения атомарными коммитами (один смысл — один коммит). Если правка трогает поведение — добавьте сценарий в `tests/smoke.sh`.
3. Откройте PR в `blackden/wireguard_vds`, дождитесь зелёного CI.

Bug-fix'ы и маленькие улучшения — без issue заранее. Большие изменения (новые скрипты, смена интерфейса существующих) — лучше сначала открыть issue для обсуждения, чтобы не делать работу впустую.
